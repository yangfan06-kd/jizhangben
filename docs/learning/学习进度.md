## 第 01 课记录（2026-10-18）

- 阅读入口：index.html、capacitor.config.json、js/storage-adapter.js、MainActivity.java。
- 讲解范围：HTML／CSS 定义界面，JavaScript 响应行为；Capacitor 使用 WebView 承载网页并连接原生能力；手机 App 与电脑浏览器的数据存储相互独立。
- 特别说明：Android 的新账本提交有原生 SQLite 保护，并兼容旧 WebView 数据；离线版不依赖可选服务端。
- 练习：解释为什么电脑打开相同代码，不会自动显示手机账目。
- 用户回答原意：“代码”部分暂时不知如何解释；认为因为使用本地 SQLite，所以不能实现迁移。
- 已能识别：手机 App 的账目保存在手机本地，另一台设备不会直接获得这份数据。
- 需要补充：代码规定程序如何工作，用户运行时产生的账目是数据；复制程序不等于复制账目。本地数据可以导出、导入迁移，但不会因此自动跨设备同步。不能把原因只归于 SQLite，本地存储的位置和未建立同步机制才是本题关键。
- 后续检查结果：用户回答“1.代码，2.数据”，正确区分“求本月总支出的计算规则”与“具体消费记录”。该判断题已通过，解释能力仍需后续复述巩固。
- 下一检查：将账目迁到新手机时，程序安装包与完整账本备份各起什么作用；此前“不能迁移”的误解是否已消除。
- 第二次回答：用户判断仅在新手机安装 APK 不能看到旧账，理由是数据在本地；同时将 APK 称为下载方式，认为同步数据需要接 USB。
- 本次反馈：仅安装程序不会带来旧设备账目，判断正确；APK 是 Android 应用安装包。迁移可通过旧机导出完整 JSON、任意可用传输方式发送、新机导入完成，USB 只是可选的文件传输手段，连接本身不构成自动同步。
- 仍待验证：能否用自己的话区分安装包、账本备份、传输方式及持续同步。不会将已纠正的参考解释当作用户已掌握。
- 第三次回答原文：“APK负责安装程序，JSON文件负责同步数据，USB不是必需品”。APK 与 USB 的作用判断已准确；JSON 仍被描述为同步工具，需要继续区分备份快照与持续同步。
- 本次补充与练习：完整 JSON 备份保存导出时的数据，传输并导入可用于迁移或恢复，不会随源设备后续记账自行更新。下一题用“上午导出、下午新增记录”的场景验证理解，答案待记录。
- 第四次回答：用户回答上午备份不会自动包含下午新账，判断正确；同时明确提出不要对细枝末节的字眼反复追问，应优先推进项目整体理解。
- 授课调整：记录关键理解即可推进；必要纠正一次说明，术语细节留作旁注，默认每课一个综合练习。用户并未完成全部原生／后端内容的独立讲解，不据此宣称已经掌握全部架构。

- 本次解释：filter 从数组中挑出符合条件的记录，返回筛选后的数组；以日期范围和类别、账户说明筛选条件。
