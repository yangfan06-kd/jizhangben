# 流水筛选

日期：2026-10-18。本节先用流水筛选认识数组的 `filter` 和条件判断，属于第 03、06 课预览。条件、回调与数组方法会在后续课程逐步巩固。

## 筛选解决什么问题

`dataState.records` 里可能有很多记录。用户选择月份、账户、类别或输入关键字后，页面要从中挑出符合条件的记录来显示。筛选得到要看的子集，完整账目仍由原记录集合管理。

## filter 的基本作用

```js
const transportRecords = records.filter(record => record.category === "交通");
```

`filter(...)` 逐笔检查 records。每次检查时，当前这一笔放在 record 里。条件成立，该笔进入 transportRecords；不成立，就跳过。结果是一个新数组，原 records 仍然包含原先的记录。

这里的 `===` 表示两边值相等；箭头函数 `record => ...` 可以先理解为“检查当前记录是否符合这个条件”。循环和回调的细节稍后学。

## 每笔记录怎样得到判断结果

项目的筛选条件较多，所以用大括号把检查过程展开：

```js
return recs.filter(r => {
  if (filterState.fromDate && r.date < filterState.fromDate) return false;
  if (filterState.category && r.category !== filterState.category) return false;
  return true;
});
```

可以把 `r => { ... }` 读作：“filter 每拿到一笔记录，就把它交给这段检查过程；当前记录叫 r。”箭头右边有大括号时，可以写多步处理。

第一条 `if` 表示：如果用户设置了开始日期，并且当前账目比开始日期早，就返回 false，filter 跳过它。第二条同理：选了类别但当前账目类别不同，就跳过。没触发排除条件时，最后返回 true，当前账目留下。

`filter` 会重复调用这个检查过程，直到看完数组中的每一笔。这个“传一段处理方法，让别的代码替你逐项调用”的结构叫回调；先理解它在这里的作用即可。

## 筛完后排序

`js/view.js` 先得到筛选结果，再按日期从新到旧排列：

```js
sorted = [...filtered].sort((a, b) =>
  b.date.localeCompare(a.date) || b.id - a.id
);
```

方括号里的 `...filtered` 把筛选结果复制到一个新数组。`sort` 按比较结果排列这个数组：先比较日期，新日期排在前面；日期相同再比较编号，较大的 id 排在前面。

这里的 `a`、`b` 是正在比较的两笔记录。暂时只需读懂排序规则，不需要掌握字符串比较的内部细节。页面顺序是展示安排，不能当作记录原本的存储位置。

## 项目里的日期筛选

js/filters.js 的 `recordsInDetailPeriod` 核心代码：

```js
return recs.filter(r => r.date >= bounds.start && r.date <= bounds.end);
```

项目日期按 `年-月-日` 保存，例如 `2026-10-18`。在这个固定格式下比较日期字符串，可以判断记录是否位于起止日期之间。`&&` 表示两个条件都要成立：不早于开始日，并且不晚于结束日。

实际函数会先处理“全部”或无有效日期范围等情况；片段只展示筛选条件。

## 多项条件与页面展示

`js/filters.js` 的 `filterByPeriod` 还检查起止日期、账户和类别。遇到不匹配项会返回 `false`，当前记录不会进入结果；满足条件则保留。

`filteredRecords()` 再调用 `matchesSearch` 检查关键字。`js/view.js` 用筛选结果绘制流水，之后才按日期排序。筛选决定留下哪些记录，排序决定这些记录怎样排列。

## 用 find 找一笔

编辑已有流水时，项目会根据记录 id 查找原记录：

```js
const record = dataState.records.find(r =>
  String(r.id) === String(uiState.editingRecordId)
);
```

`find` 也会逐项检查，但它找到第一笔符合条件的记录后，就返回这笔对象；没有找到则返回 `undefined`。因此，筛选并显示多笔用 `filter`，按唯一 id 定位一笔用 `find`。

真实保存流程随后把编辑内容应用到这笔记录；新增记录则走 `push` 分支。id 用于识别账目，当前数组索引可能因新增或展示排序变化。

## 用 reduce 合计金额

首页和流水统计还需要把多笔金额加起来。`reduce` 可以逐笔处理记录，最后把许多值收成一个结果：

```js
const totalCents = records.reduce(
  (total, record) => total + record.amountCents,
  0
);
```

这里的 `0` 是合计的起始值。每看一笔，`total` 表示目前累计金额，`record` 是正在处理的记录；返回“累计金额＋这笔金额”，再把结果交给下一笔。两笔分别为 1800 和 2500 分时，最终结果是 4300 分。

项目的 `js/view.js` 使用 `reduce` 分别汇总收入和支出，并通过 `incomeEffect`／`expenseEffect` 先求每笔记录对该统计的影响。这样退款、报销等类型不会简单地把记录的原始 amount 一律相加。

至此几个数组方法各有用途：`filter` 挑出多笔，`find` 找到一笔，`reduce` 汇总成一个结果。项目的类别汇总也可以使用循环逐笔累计，读代码时先认清目的，不要求写法只有一种。

## 用 map 逐项生成页面内容

项目的 `js/view.js` 用 `DETAIL_PERIODS.map(...)` 逐项生成“今天、本周、本月、本年”的汇总按钮。简化后像这样：

```js
const names = periods.map(period => period.name);
```

每个输入项 `period` 会变成一个输出项 `period.name`，所以 `map` 适合“数量对应、内容转换”。它返回新的数组，原数组用来保存原始选项。真实页面中，每个 period 会被转换成一段按钮 HTML 字符串，最后 `.join("")` 将这些字符串连起来交给页面展示。

现在这几种方法可按想完成的工作辨认：找一组用 `filter`，找一笔用 `find`，逐项转换用 `map`，多项累计为一个值用 `reduce`。

## 一个综合练习

虚构流水有三笔：餐饮、交通、交通。筛选“类别是交通”后，结果有几笔？原数组里的餐饮记录会被删除吗？用自己的话说明即可，不要求背 `filter` 语法。

用户回答：“2,不会”。结果数量和原数组是否保留均正确。随后解释了 filter 逐笔调用箭头函数及 true／false 的作用；语法细节仍待巩固。用户又正确说明了同日同类时，id 可精确定位单笔记录，并回答两笔 1800、2500 分合计为 43 元；正确判断 map 将四个时期生成四个按钮。数组方法的回调写法仍需巩固。
