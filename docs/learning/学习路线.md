# 记账本项目学习路线

制定日期：2026-10-18。用途：本窗口专门用于理解当前项目、练习、排错和准备实习交流，不在学习过程中直接改动生产功能、真实账本或手机安装。

## 学习起点与目标

用户为软件工程专业大二学生，自述了解 HTML／CSS，JavaScript 还不熟。因此先补齐阅读本项目必需的 JavaScript，再追踪真实业务，不直接从整段复杂保存逻辑或数据库事务开始。

目标是能独立说明项目结构、追踪一笔记录、解释关键取舍、用合成数据复现和定位问题，并准确区分自己独立完成、协作完成及仍未掌握的部分。开发日志中的“完成”不能直接转换成学习进度中的“掌握”。

当前阅读目录是 `G:/project/jizhangben-publish`。`G:/project/jizhangben` 是另一个检出目录，两者可能不同；本课程以当前阅读目录内的实际代码为准。当前前端为 HTML／CSS／普通 JavaScript，多脚本按顺序加载，通过 Capacitor 和 Android 原生代码组成离线应用；FastAPI／SQLite 服务端属于另一种可选运行路径，不是离线记账的依赖。

## 课堂约定

1. 每次只讲一个可验证的目标。先讲作用和结构，再看必要的代码；不逐字符翻译，也不一次堆满术语。
2. 每个新术语先用项目中的具体例子解释，再给正式名称；先能读懂、预测结果，再要求独立写代码。
3. 先用一笔“微信支出 12 元餐饮”的简单路径串联项目，再逐步增加转账、押金、基金与自动记账。
4. 一课通常安排 40—60 分钟，可拆成多次。建议每周 2—3 次，实际速度按理解情况调整，不承诺固定几周掌握全部项目。
5. 练习只使用纸笔、独立示例或隔离内存的虚构数据；需要代码时放在本学习目录下。不导入家人账本、不连接正式手机存储、不把练习写入生产页面。
6. 开发窗口若修改了相关模块，下一次课先核对差异，不把过时函数名或旧版本说明当成当前事实。
7. 学习发现疑似缺陷时先记录证据和验证边界；实际修复转到开发流程处理。假设案例与真实故障分别标记。
8. 用户于 2026-10-18 明确要求以理解项目主线为先，不反复纠缠细枝末节的措辞。意思准确即可继续；只在误解会影响实现、数据安全或核心原理时及时纠正。默认每课一个综合练习，不对同一概念连续逐词追问，术语细节随真实代码阅读再巩固。

## 每次学习的流程

| 环节 | 做什么 | 留下什么 |
| --- | --- | --- |
| 回顾 | 不看笔记复述上次的关键流程 | 尚未理解的问题 |
| 解释 | 说明这个部分解决什么问题、输入输出是什么 | 小范围结构图或代码标注 |
| 阅读 | 看真实文件中的必要结构与调用关系 | 函数、字段和调用位置 |
| 练习 | 预测结果、追踪数据、改写独立示例或定位一个错误 | 自己的答案及验证结果 |
| 追问 | 按需提出一个关键追问，不把每个术语都设成过关题 | 真实理解与待补点 |
| 归档 | 更新进度、知识、问题和待复习项 | 学习日志及下一课入口 |

## 分阶段课程

文件路径相对于当前项目目录。表中列的是阅读入口，不要求一次通读整个文件。

| 一／01 | 项目全景：`index.html`、`js/app.js`、`capacitor.config.json`、`backend/app/main.py` | 画出网页、Android 外壳、本地数据和可选服务端之间的关系 |
| 二／02 | 变量、类型和转换：`js/helpers.js` 的 `toCents` | 分清字符串金额和数字金额，预测转换结果 |

| 二／05 | 对象、数组、引用和复制：`js/state.js`、`normalizeRecord` | 说明修改草稿为什么可能意外影响原对象 |
| 二／06 | 回调与数组方法：`map`、`filter`、`find`，逐步引入 `reduce` | 用三笔虚构账目完成筛选和求和 |

## 学习验收

每课分别检查：

- 能不看标准答案，用自己的话解释作用和数据流。
- 能在真实代码中指出相应函数、字段及调用处。
- 能完成一个独立小练习，或预测正常与异常场景的结果。
- 随课程逐步能解释“为什么这样设计”以及重要失败场景，不要求每课反复通过术语问答。

进度使用“未开始／学习中／待复习／已掌握”。“已掌握”必须有用户实际回答或练习证据；助手讲完、测试全部通过或文件已经生成，都不能作为用户掌握的证明。基础理解已达到时可以继续下一课，把深层细节标为后续复习，不要求当前课一次掌握全部细节。复习发现薄弱点可以回到“待复习”，不把它视为失败。

每完成约三课安排一次串联复习，每完成一个阶段安排一次口述与独立练习。面试表达先保证准确、具体，再练习简洁。

## 实习表达的准确性

允许明确说明项目在 AI 辅助下推进，并讲清本人负责的需求、验证、阅读、决策和独立实现。未经独立完成的内容不要改写成个人独立成果；隔离测试不要说成所有用户手机都已升级验证；应用锁不要说成银行级加密；已有服务端不要说成所有业务已实现可靠跨端同步。

最终应准备：一张架构图、一条记账调用链、三次真实问题复盘、两个能说明边界的设计取舍，以及一个可以现场独立完成的小练习。具体措辞由实际掌握证据决定。
