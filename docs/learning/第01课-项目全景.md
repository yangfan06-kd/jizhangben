# 第 01 课：你的记账本由哪些部分组成

状态：2026-10-18 首轮讲解与基础概念判断完成；平台结构细节在后续代码阅读中复习。按用户要求，不再逐词追问同一概念。

## 这一课只解决一个问题

能说明“用户看到的页面、程序处理的账目、手机保存的数据、Android 安装包”之间是什么关系。暂时不用读懂每行 JavaScript。

## 先看整体

```text
使用者点击、输入
        ↓
HTML 页面结构 + CSS 样式
        ↓ JavaScript 事件
界面状态／账本数据 → 校验和账务规则 → 更新页面
                         ↓
                    存储适配接口
                    ↙          ↘
        浏览器 localStorage    Android 原生桥接 → SQLite

可选服务端：网页请求 → HTTP API → FastAPI → 服务端数据库
```

这是阅读地图，不是声称所有代码已经严格分成完全独立的层。当前 JavaScript 仍有共享状态、全局函数和普通 script 加载顺序，后面会逐步识别它们的依赖。

Android 数据读取也有兼容过程：原生端优先提供已经明确提交的账本键，没有原生值的旧键继续从 WebView 存储读取。不能把图理解成更新后直接清空旧存储、全部重建 SQLite。

## 各部分负责什么

| 部分 | 在本项目里做什么 | 第一次只看哪里 |
| --- | --- | --- |
| HTML | 定义记账页、按钮、表单等结构 | `index.html` 的金额键盘和末尾 script 列表 |
| CSS | 控制大小、间距、颜色和屏幕适配 | `css/style.css`，本课只知道其用途 |
| JavaScript | 响应操作、组织数据、计算、保存和渲染 | `js/state.js` 与 `js/app.js` |
| Capacitor | 将网页应用装进原生容器，连接部分系统能力 | `capacitor.config.json` |
| Android 原生代码 | 处理返回、下载目录备份和原生持久化等 | `MainActivity.java`、`LedgerStore.java`，暂不要求读懂 Java |
| 可选服务端 | 提供账号及服务端数据接口 | `backend/app/main.py`，暂不要求读懂 Python |
| 测试 | 用可控制的例子检查行为与失败处理 | `tests/`，本课不执行测试 |

## 当前最重要的三点

第一，网页代码可以成为 Android 应用的界面。Capacitor 使用 WebView 显示这些网页，同时允许 JavaScript 请求原生能力。APK 里既有网页资源，也有原生工程生成的内容。

第二，页面上的文字不等于已保存的数据。输入金额时可以先改变界面状态；只有通过校验并成功保存，才算写入账本。页面显示成功、内存存在和磁盘已经提交，是后面要分别验证的状态。

第三，离线 App 和服务端模式不是同一条运行路径。当前个人离线版不需要电脑开机、USB、Docker 或服务器；服务端代码存在，不代表离线 App 每记一笔都向服务器发送请求，也不代表已经实现全部业务的多端同步。

## 三个阅读动作

1. 在 `index.html` 中找到 `recordKeyboard` 和按钮的 `data-record-key`。现在只观察按钮显示的数字与属性值，不修改代码。
2. 翻到 `index.html` 末尾，找到 `js/state.js`、`js/storage-adapter.js`、`js/app.js`，观察普通脚本的排列。排列存在依赖，不能随意认为换顺序也一样。
3. 打开 `js/state.js`，找到 `uiState` 和 `dataState`。先尝试理解“当前打开哪个页面”和“已有多少笔流水”为何是两类数据，不要求背字段。

## 本课第一次回答与补充

用户能识别账目保存在手机本地，对代码部分暂不清楚，并认为使用本地 SQLite 意味着不能迁移。

需要区分：

- 代码：定义界面、输入处理、计算、保存等行为。相同程序可以操作不同用户的数据。
- 数据：用户运行应用后实际保存的账目。复制或安装程序，不会自动复制另一个设备中的账目。
- 迁移：将已有数据带到另一个环境，本项目可通过导出完整 JSON、在另一设备导入实现；兼容性与恢复需要验证。
- 自动同步：设备之间持续传递和处理变化，需要另外的同步机制，不能由“使用同一套代码”或“都使用 SQLite”直接得到。

这属于概念理解的待补点，不是新的生产故障。下一次复述验证前，本课保持学习中。

## 换机练习补充：APK、JSON 与 USB

用户正确判断仅安装 APK 无法带来旧手机账目，但认为同步需要 USB。

- APK 是 Android 应用安装包，负责安装程序；微信等是获取或发送这个文件的方式。
- 完整 JSON 备份承载导出时的账本内容。旧手机导出、将备份文件送到新手机、新手机导入，可以完成一次迁移。
- USB 是可选的文件传输通道，也可以使用微信文件等可用方式。传输通道不会自行决定哪个文件是账本，也不会自动导入或保持两台设备后续数据一致。
- 持续自动同步要额外实现变化传递、处理与冲突规则，例如通过服务端。当前个人离线版不因连接 USB 或安装相同程序而自动获得此能力。

课堂在讲解迁移概念，不操作真实设备或执行导入。
