# 记账本手机端界面进化路线（2026-09-18）

## 目标与边界

当前目标是让家人可以独立安装和使用的 Android 离线记账本。先改善每天都要用的“看流水、记一笔、查余额”，再完善图表和个性化。沿用现有 HTML/CSS/JavaScript + Capacitor，不因界面改造重写业务层；押金全退不计收支、少退差额计支出等计算规则保持不变。

用户提供的随手记截图仅作为信息层级与操作路径参考，不复制它的插画、图标、配色或页面资产。截图中值得学习的是：账本信息与记一笔分屏；记一笔时金额最突出，类别、账户、日期、备注按顺序出现；底部入口固定且含明确的新增动作。它的宣传条、AI、成员、客服、借贷、预算与拍照功能目前不符合个人离线版的优先级。

## 当前项目的具体问题

- `index.html` 把月度统计卡片放在所有四个页面上方，记账前必须先经过汇总、导航和表单标题；“记一笔”默认承担首页职责。
- 类型与类别都以多行胶囊按钮呈现，还混入“展开”和“自定义”；金额、账户、日期和备注与这些选项一起平铺在同一张卡片中。
- 顶部账本切换、管理、登录状态、四个标签同时争夺手机宽度。离线版仍显示登录相关入口，容易让家人误以为必须注册。
- 明细页同时放日期、账户、类别、搜索、汇总、折叠按钮和图表；查一笔账需要经过过多控件。
- Web 图标与 Android 启动图标还没有统一的自有视觉规范；当前 `android/app/build.gradle` 为 `versionCode 1`，发给家人的 APK 是调试签名版。

## 拟定的手机端结构

1. **流水（默认页）**：顶部显示当前账本与切换入口；本月摘要只保留一张简洁卡片，明确区分“本月结余”和“账户净资产”；下面直接是最近账目。搜索和筛选收在一个可展开区域。
2. **报表**：按月查看收入、支出、结余趋势与类别分布；图表在这里集中展示，避免与流水筛选混在一起。押金收付与结算仍按现有业务口径计算。
3. **账户**：查看资金/负债账户余额，增改账户在独立面板完成。
4. **记一笔**：底部固定、带文字的显著按钮打开独立录入页；顶部先选“支出 / 收入”，金额为第一焦点；接着类别、账户、日期、备注。转账、押金及自定义类型从“更多类型”进入，选中后才出现专属字段。
5. **账本与设置**：账本管理、备份导入导出、应用版本和未来的联网入口集中放在次级页面。离线版主界面不显示不可用的登录/同步动作。

导航建议采用“流水 / 报表 / 账户”三个稳定目的地，加一个固定“记一笔”动作；账本与设置由顶部入口打开。安卓设计指南把底部导航用于 3–5 个同级目的地，录入动作本身不是一个长期停留的页面，因此独立按钮更清楚。见 [Android 导航模式](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns)。

## 视觉方向草案

- 采用安静的浅色底、深色正文和一个明确的主操作色；首页不用大幅照片背景，让金额与流水承担视觉重点。保留现有收入/支出文字和正负号，即使色弱或黑白显示也能辨认。
- 用固定的间距梯度整理页面：页面左右约 16px，卡片内部约 16–20px，大区块间约 24px。金额字号明显大于说明文字，减少同等大小的标题互相竞争。
- 导航与操作图标使用同一套约 24px 的线性 SVG，线宽、圆角和留白一致；账户、报表、流水、添加、备份各有固定语义。类别图标先覆盖常用项，自定义类别保留文字回退，不因缺图标阻止记账。
- Android 桌面图标单独设计简洁的“账本/记账”识别符，生成前景、背景及单色层，并在圆形与圆角矩形遮罩下检查，避免直接把网页 favicon 放大。

先完成第 0 步，再按 1→2→3→4→5 前进。每一步只交付一个可测试的版本，在 `docs/LEARNING_LOG.md` 记“改了什么、为什么、失败点、验证证据”，并把可用于面试的技术决策写到 `docs/INTERVIEW_NOTES.md`。

## 设计约束

- 录入页面默认只显示当前操作必要字段；选择押金类型后，关联原记录、最终结算差额提示必须清楚呈现。
- 统计卡片只讲一种口径：月度结余属于期间收支，净资产属于账户余额；标题不能混用。
- 图标须有文字或无障碍名称，收入/支出不能只用颜色区分；保留明显的焦点样式。触控目标按约 48px 设计，参考 [Android 触控目标建议](https://developer.android.com/develop/devices/chromeos/learn/design)。
- 图片和图标仅使用自行绘制或许可清楚的素材，并记录来源；优先 SVG，不用 emoji 充当功能图标。Android 启动图标按[自适应图标规范](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive)制作。
- 手机端的固定底栏必须避开系统手势区域，表单必须避开软键盘；参考 [Android 系统栏建议](https://developer.android.com/design/ui/mobile/guides/foundations/system-bars)。
- 不改已有备份格式、记录 ID 和金额计算；每个可安装版本在发给家人前先做本地数据回归。

## 优先处理的升级风险

当前分发文件为调试 APK，而正式发布 APK 目前未配置签名。Android 覆盖更新要求包名、签名证书匹配，并要求新版本号满足更新规则；改用另一把签名密钥会使现有安装无法直接升级，若卸载重装则可能清除本地数据。下一步先保留当前 APK 与签名信息，让已使用的手机导出备份，再决定长期签名方案，并用非真实账本演练迁移。见 [Android 更新条件](https://developer.android.com/google/play/app-updates) 与 [应用签名](https://developer.android.com/studio/publish/app-signing)。
