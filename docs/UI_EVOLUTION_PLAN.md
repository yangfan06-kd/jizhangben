# 记账本手机端界面进化路线（2026-09-18）

## 目标与边界

当前目标是做一款家人能独立安装、普通用户首次接触也容易上手的 Android 离线记账本。界面以**普适性、易上手**为核心：不预设性别、年龄或特定消费习惯；先让人看懂“记一笔、看流水、查余额”，再完善图表和个性化。沿用现有 HTML/CSS/JavaScript + Capacitor，不因界面改造重写业务层；押金全退不计收支、少退差额计支出等计算规则保持不变。

用户提供的随手记截图及姐姐正在使用的记账页截图，仅作为信息层级与操作路径参考，不复制它们的插画、图标、配色或页面资产。姐姐明确喜欢“简洁明了”：打开记账页就能选支出/收入/转账和常用分类，金额与保存操作一直清楚可见。宣传条、AI、成员、客服、借贷、预算与拍照功能目前不符合个人离线版的优先级。

姐姐的反馈是设计线索，不把她的审美当作所有用户的偏好。首用体验要有清楚的空状态与下一步入口；日常操作用常见词和文字图标，不依赖颜色或财务术语；默认账户、日期与类别要可见可改，出错后能理解并修正。

**全中文界面是硬性要求。** 应用内所有用户可见文案都使用中文，包括导航、按钮、字段、占位提示、弹窗、空状态、加载状态、成功/失败反馈、设置、备份与更新说明。按钮写“确定 / 取消 / 保存”，不出现 `OK`、`Cancel`、`Save` 等英文。技术标识只留在代码、接口和文件格式中，不直接展示给用户；用户自己输入的英文内容照原样保留。

新增的市场调研见 [`MARKET_UI_RESEARCH.md`](MARKET_UI_RESEARCH.md)：以小米记账分类榜单挑选国内样本，以 Google Play 公开的 `10M+` 安装量区间挑选国际样本。两种口径不可互相排名；界面判断区分用户截图、官方帮助页和商店介绍。调研支持“快速录入、清楚的账户/日期、分开看账与记账”，不要求照搬任何竞品页面。

## 当前项目的具体问题

- `index.html` 把月度统计卡片放在所有四个页面上方，记账前必须先经过汇总、导航和表单标题；“记一笔”默认承担首页职责。
- 类型与类别都以多行胶囊按钮呈现，还混入“展开”和“自定义”；金额、账户、日期和备注与这些选项一起平铺在同一张卡片中。
- 顶部账本切换、管理、登录状态、四个标签同时争夺手机宽度。离线版仍显示登录相关入口，容易让家人误以为必须注册。
- 明细页同时放日期、账户、类别、搜索、汇总、折叠按钮和图表；查一笔账需要经过过多控件。
- Web 图标与 Android 启动图标还没有统一的自有视觉规范；当前 `android/app/build.gradle` 为 `versionCode 1`，发给家人的 APK 是调试签名版。
- 新用户从空账本到第一笔账的路径、空状态提示与保存反馈尚未按“无需旁人讲解”验收；已有使用者觉得简洁，不等于第一次使用的人也会懂。
- 当前登录邮箱示例仍是 `you@example.com`，部分删除/导入操作使用浏览器原生 `confirm`，确认按钮文字可能受 WebView/系统语言影响；改版时需换成应用自有的中文提示与确认组件，并逐屏检查动态报错。

## 拟定的手机端结构

1. **流水（默认页）**：顶部显示当前账本与切换入口；本月摘要只保留一张简洁卡片，明确区分“本月结余”和“账户净资产”；下面直接是最近账目。搜索和筛选收在一个可展开区域。
2. **报表**：按月查看收入、支出、结余趋势与类别分布；图表在这里集中展示，避免与流水筛选混在一起。押金收付与结算仍按现有业务口径计算。
3. **账户**：查看资金/负债账户余额，增改账户在独立面板完成。
4. **记一笔**：底部固定、带文字的显著按钮打开独立录入页；上方先选“支出 / 收入 / 转账”，随后看到常用分类图标与名称。金额和唯一的“保存”按钮固定在下方操作区，账户、日期、备注在两者之间。押金和自定义类型从“更多类型”进入，选中后才出现专属字段。
5. **账本与设置**：账本管理、备份导入导出、应用版本和未来的联网入口集中放在次级页面。离线版主界面不显示不可用的登录/同步动作。

导航建议采用“流水 / 报表 / 账户”三个稳定目的地，加一个固定“记一笔”动作；账本与设置由顶部入口打开。安卓设计指南把底部导航用于 3–5 个同级目的地，录入动作本身不是一个长期停留的页面，因此独立按钮更清楚。见 [Android 导航模式](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns)。

### 记账页的第一版草图

```text
取消                 记一笔
       支出  收入  转账   更多

常用分类：图标 + 名称，直接点选
餐饮  交通  购物  居住  其他
展开全部分类 / 自定义类别

账户：微信       日期：今天
备注：选填

金额 ¥0.00
数字输入区              保存
```

常用分类先用现有类别映射，不改变历史账目的类别名称；自定义类别没有图标时显示统一占位符和文字。完整类别以展开区呈现，避免把常用项在“全部分类”里重复排列。账户、日期须能查看和修改，不能因有默认值而完全消失。录入页只保留一个明确的保存动作。

“常用分类”第一版先取固定的 4–6 个高频默认类别，再通过家人的真实使用调整；不要从别人 App 的分类名称推断本项目用户习惯。普通支出的任务目标是：打开录入页后能立即看到当前类型、账户、日期和分类；选类别、输入金额、保存后在流水中找到刚才的记录。点击次数、完成时间与误选记录作为试用数据，不设未经实测的“3 秒记账”承诺。

首次启动或空账本时，页面要说明下一步能做什么，并给出“记一笔”等明确入口；如果还缺少必需的账本或账户，引导完成设置后回到刚才的任务。术语用“转入账户/转出账户”“本月收入/支出”等具体名称；错误提示指出需要修改的字段。保存成功后明确展示新记录，并允许进入明细修改。

先用系统数字键盘完成可操作原型，并在真机验证页面位置、金额与保存是否始终可见；若系统键盘造成遮挡或跳动，再实现应用内数字键盘。数字键盘的加减快捷计算不进入第一轮，避免改变金额输入与校验规则。

## 视觉方向草案

- 采用安静的浅色底、深色正文和一个明确的主操作色；首页不用大幅照片背景，让金额与流水承担视觉重点。保留现有收入/支出文字和正负号，即使色弱或黑白显示也能辨认。
- 视觉风格保持中性和克制，避免把粉色、卡通或金融专业风格设为默认；以后若增加主题，也不能改变按钮位置和基本操作顺序。
- 用固定的间距梯度整理页面：页面左右约 16px，卡片内部约 16–20px，大区块间约 24px。金额字号明显大于说明文字，减少同等大小的标题互相竞争。
- 导航与操作图标使用同一套约 24px 的线性 SVG，线宽、圆角和留白一致；账户、报表、流水、添加、备份各有固定语义。类别图标先覆盖常用项，自定义类别保留文字回退，不因缺图标阻止记账。
- Android 桌面图标单独设计简洁的“账本/记账”识别符，生成前景、背景及单色层，并在圆形与圆角矩形遮罩下检查，避免直接把网页 favicon 放大。

## 设计约束

- 录入页面默认只显示当前操作必要字段；选择押金类型后，关联原记录、最终结算差额提示必须清楚呈现。
- 统计卡片只讲一种口径：月度结余属于期间收支，净资产属于账户余额；标题不能混用。
- 图标须有文字或无障碍名称，收入/支出不能只用颜色区分；保留明显的焦点样式。触控目标按约 48px 设计，参考 [Android 触控目标建议](https://developer.android.com/develop/devices/chromeos/learn/design)。
- 图片和图标仅使用自行绘制或许可清楚的素材，并记录来源；优先 SVG，不用 emoji 充当功能图标。Android 启动图标按[自适应图标规范](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive)制作。
- 手机端的固定底栏必须避开系统手势区域，表单必须避开软键盘；参考 [Android 系统栏建议](https://developer.android.com/design/ui/mobile/guides/foundations/system-bars)。
- 不改已有备份格式、记录 ID 和金额计算；每个可安装版本在发给家人前先做本地数据回归。
- 面向不同记账习惯保留类别和账户自定义；首用流程不要求理解“净资产”等术语。文字、图标、焦点和较大字号共同提供可读性，不能只依靠粉色或其他主题表达状态。
- 逐屏检查应用自有的静态与动态文案，尤其是错误、网络异常、备份导入、删除确认、空数据和加载状态；避免让原生 `alert`/`confirm` 或后端英文错误直接成为用户看到的界面。程序内部字段名、接口路径及用户自填内容不受此规则约束。

## 优先处理的升级风险

当前分发文件为调试 APK，而正式发布 APK 目前未配置签名。Android 覆盖更新要求包名、签名证书匹配，并要求新版本号满足更新规则；改用另一把签名密钥会使现有安装无法直接升级，若卸载重装则可能清除本地数据。下一步先保留当前 APK 与签名信息，让已使用的手机导出备份，再决定长期签名方案，并用非真实账本演练迁移。见 [Android 更新条件](https://developer.android.com/google/play/app-updates) 与 [应用签名](https://developer.android.com/studio/publish/app-signing)。
