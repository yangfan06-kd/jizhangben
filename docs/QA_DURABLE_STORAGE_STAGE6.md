# 阶段 6：断网、三键导航与保存落盘修复（2026-10-17）

补测真实断网和三键导航时，复现了一个发布阻断问题：确认记账后立即强制停止进程，WebView 偶尔尚未把 localStorage 写入磁盘。初轮两次快速停止中一次重开仅有原先一笔，刚确认的 10 元记录消失，净资产回到 87.66 元。问题发生在独立合成测试包，正式账本没有被操作。

已增加 Android 原生同步提交保护。修复后同样断网、保存后不增加稳定等待的五次快速停止全部保留新记录，净资产均为 77.66 元；其中四次 WebView 副本仍过旧，但应用从原生存储读回完整值。这是本机实测范围，不代表断电、损坏介质或所有机型已验证。

## 修复范围

| 文件 | 改动 |
| --- | --- |
| `android/app/src/main/java/com/jizhangben/app/LedgerStore.java` | 新增原生 SQLite 键值提交层。事务完成并成功返回后才确认写入；失败返回失败。只接受 `jizhangben_` 键，删除保留 NULL 标记，防止过旧副本复活已删除内容。 |
| `android/app/src/main/java/com/jizhangben/app/MainActivity.java` | 仅增加 `JizhangbenStorage` 接口注册，原备份、返回和系统栏实现不变。 |
| `js/storage-adapter.js` | 原生端读取已提交的变更键，未进入原生存储的旧键仍读取原 localStorage。写入先确认原生事务，WebView 作为兼容副本；浏览器和旧壳继续原路径。批量恢复使用一次事务。 |
| `js/backup.js` | 原生恢复通过适配层整份原子替换，避免停止在删除旧值与写入新值之间；浏览器保留原快照回滚分支。 |
| `tests/storage-adapter.test.cjs`、`package.json` | 新增八项有独立故障／重开模拟的回归并纳入测试命令，没有新增依赖。 |

数据库位于应用私有目录，名为 `ledger-durable.db`。首次读取只创建空存储结构，**不复制默认类别、不重建账本、不改写原记录**；只有用户或原有业务明确写入／删除的键才进入原生层。旧账本键名、金额精度、类别编号、排序、隐藏项及 JSON 备份格式均沿用。设备密码、隐私开关和草稿仍走原设备设置路径，没有扩大这轮改动。

原生读取失败时不把失败当作空账本，而是给出中文提示并阻止后续写入；原生提交失败沿用原保存失败反馈并恢复内存。已提交值不因 WebView 副本写入失败而丢弃。读取原生层只在页面首次需要时进行并缓存，正常展示不逐字段跨桥查询；每次写入增加同步提交成本，大批量长期写入性能仍需后续测量。

正常升级保留应用私有数据。旧 APK 不认识新增原生存储，因此本轮不承诺版本回退兼容；不要用卸载后重装代替覆盖更新。备份导出从统一适配层取得完整最新值，仍是原 JSON 格式，可用于迁移。

## 失败证据与边界

初次断网测试错误依赖 `navigator.onLine`。设备默认网络已断开、旧账目正常加载，但 WebView 仍报告 true；后续保留该观测，改用真实系统网络状态作为断网证据，没有模拟浏览器网络或放宽金额／记录判据。

随后的一项复合断言未通过，最初日志不足以区分网络和数据原因。追加独立快速停止实验后，明确捕获到最后一笔在 WebView 磁盘副本丢失，不能将它归为脚本误差。修复后五次实验同时保留原始 WebView 与统一读取值，以证明修复实际抵抗了这个窗口。

原生错误重试脚本第一次没有重新打开已收起的数字键盘，未真正点击到确认；按原有交互先点击金额再重试后通过。原失败报告保留。测试期间发现用户切换到其他应用，暂停手机操作并再次取得空闲授权后才继续。
