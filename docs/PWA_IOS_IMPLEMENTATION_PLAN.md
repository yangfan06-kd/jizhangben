## 目标与范围

将现有记账本扩展为 iPhone 可通过 Safari 打开、添加到主屏幕、首次成功缓存后离线使用的 PWA。沿用中文页面、类别、账户和既有记账规则，继续提供安卓 APK。

首版使用免费静态托管的固定 HTTPS 地址，账目在用户设备本地处理。无需购买苹果开发者会员或自建云数据库；免费服务的额度、可访问性和持续可用性需要在部署时核验。暂不增加账号同步、自动云备份、推送或关闭应用后的定时运行。基金和退休金继续在打开应用时按既有规则补记。

## 当前基线与保护要求

- 当前 Android 工程版本为 2.08／109；本地还有报销类别等未提交修改，实施前应保存准确的源码和 APK 摘要，不能从旧 GitHub 版本直接开始覆盖工作目录。
- 页面采用 HTML/CSS/原生 JavaScript，Capacitor 是安卓原生壳。业务代码可复用，但本机 SQLite 与备份桥接不能直接用于 iPhone 网页。
- 当前普通浏览器使用 localStorage；appStorage 接口及大量调用为同步形式。接入异步数据库不能只返回 Promise 而让原调用者继续显示成功。
- HTTP 页面存在服务端登录路径。PWA 必须使用独立离线运行配置，初始化顺序要在业务脚本之前，避免误请求不存在的 API。
- 当前未发现完整 PWA 安装清单及 Service Worker 注册。现有 JSON 备份格式继续作为迁移出口。
- 不清空真实用户数据，不批量重建类别，不自动覆盖导入；Android 包名、签名、财务语义保持兼容。测试优先用合成账本与独立测试站点。

## 阶段 0：锁定基线与测试入口

工作：保存当前差异清单、源码/包摘要、回归结果；标出原生桥接、同步写入、备份、启动登录和周期补记入口。规划 PWA 专属构建产物目录，禁止直接发布整个项目根目录。

交付：基线清单、风险清单、测试夹具。只有现有改动已被保护且明确哪些文件可公开时，进入下一阶段。

## 阶段 1：独立 PWA 构建与桌面入口原型

工作：

1. 添加 Web App Manifest、中文应用名称、桌面图标、启动路径、独立窗口显示及 iOS 所需元信息；正确处理域名子路径与安全区域。
2. 单独生成离线 runtime-config，禁止 PWA 默认进入服务端登录，不使用安卓 API 地址或要求电脑后台运行。
3. 构建输出只允许页面、业务 JS/CSS、离线图标、安装清单、运行配置和 Service Worker 等明确资源；禁止包含备份、密钥、学习笔记、临时截图及后端数据库。
4. 建立安装说明：微信接收链接 → 用 Safari 打开 → 添加到主屏幕；安装按钮不假装能代替 iPhone 系统操作。

验收：本地示例页面可完成基本操作；网络检查没有意外 API 或第三方资源请求；原安卓构建仍可工作。此阶段只交付原型，不建议用户存放唯一正式账本。

## 阶段 2：浏览器存储可靠性（正式试用的前置条件）

目标方案：PWA 使用 IndexedDB 事务保存账本，维护启动后内存读取视图；设备选择偏好单独管理。Android 继续使用既有原生 SQLite 路径。IndexedDB 同样受网站数据管理，不能承诺永久保存。

实施顺序：

1. 先用独立样例验证数据库开启、事务提交、读回与重启恢复；评估现有存储适配层的改动范围。
2. 遍历所有写入入口，包括新增/编辑/删除、账户、类别、账本、预算、基金、退休金、周期补记和导入。异步提交确认前不显示成功或清空表单；提交失败保留输入与原状态，阻止重复点击和并发冲突。
3. 启动先等待存储准备完成，再加载账本和执行补记。读取失败要停止危险写入，不能把失败当空账本初始化。
4. 兼容旧网页数据时采用“读取原副本 → 校验 → 事务写入 → 读回核对 → 标记完成”，不先删除 localStorage；标记与账本提交保持一致。原副本不在本批自动清理。
5. 对不支持、被禁用或无法打开的持久数据库提供明确中文状态，不能静默切到另一空存储继续记账。处理多窗口旧内存覆盖新记录的问题。
6. 请求并显示 persistent storage 的实际状态；未获批准时如实提示备份，不把“已请求”显示为“已保护”。

验收：保存、快速关闭重开、连续操作、写入失败、数据库打开失败、旧数据迁移、多窗口更新、周期补记去重通过；Android 相关回归通过。更换存储不改变流水、金额、类别、图标、排序或隐藏项。

## 阶段 3：备份、恢复与风险提示

工作：

- 继续使用可互通的 JSON 账本备份，兼容安卓旧版导出；先预览再由用户确认替换。损坏、取消、空间不足或恢复中断时保留原账本。
- 验证 iPhone 上“保存到文件”和从“文件”选择导入。浏览器发起下载或分享不等于已保存，不在无法确认落盘时显示确定成功。
- 显示上次备份操作状态，并提供可忽略的定期提醒；没有权限时不承诺自动保存到 iCloud。
- 用简洁中文说明：账目在本机；清理数据、删除网页应用、换机等情况可能影响记录；持久存储并非独立备份。

验收：样例账本导出到文件后可重新选择并恢复；逐项比较流水、账户、类别、图标、顺序和隐藏项。安卓 → PWA、PWA → 安卓均使用隔离副本检查。不要将“格式能解析”当成实际 iPhone 文件操作通过。

## 阶段 4：离线缓存与更新

本机实施结果见 [PWA_STAGE4_OFFLINE_UPDATE.md](PWA_STAGE4_OFFLINE_UPDATE.md)：程序资源完整核对、断网打开、显式更新、草稿保护及旧缓存保留已检查；真实 iPhone 行为仍待阶段 5。

工作：

- Service Worker 仅缓存允许列表里的程序资源，不缓存账目备份或接口响应；首次缓存全部成功后才显示“可离线使用”。缓存不完整时不能误报。
- 离线情况下，桌面重新启动、切换页面、分类图标和金额键盘都应可用。网页资源缓存与账本数据库分开管理，清理旧资源缓存不能删除账本。
- 版本资源要一致，避免新 HTML 加载旧 JS；新版本就绪后用中文提示，在用户完成/保留草稿且没有写入事务时切换，不强制中途刷新。
- 模拟更新下载中断、缓存失败、旧页面仍打开、资源回退。程序可回退不代表数据库可任意回退；数据结构变更需要明确迁移及兼容策略。
- 正式域名/协议/路径及 Web App 身份尽量稳定。迁移站点地址时先提供备份迁移流程，不把新地址的空账本误判为旧数据被清除。

验收：先联网准备，再真断网关闭重开；A 版有非空账本及自定义类别，升级 B 版后逐项保留。加载失败时保留可用旧版与数据。

## 阶段 5：Windows 自动检查与 iPhone 验收

阶段 5A 结果见 [PWA_STAGE5_ACCEPTANCE.md](PWA_STAGE5_ACCEPTANCE.md)，两套浏览器的小屏/大字及返回交互检查通过；真机任务已整理为 [PWA_IPHONE_ACCEPTANCE.md](PWA_IPHONE_ACCEPTANCE.md)，当前全部标记待测。

Windows 检查：Chrome/Edge 与 Playwright WebKit、小屏/大字、金额及关联结算、筛选和按日汇总、草稿提示、类别管理、离线冷启动、备份恢复、升级和失败注入。WebKit 检查不等于真实 iPhone Safari 验收。

已确认设备条件：用户没有 iOS/macOS 设备，开发期间由我们完成可执行的自动检查与模拟验证；产品完成后再借用他人设备验收。记录每项实际结果，不以模拟测试替代真机结论。

真实 iPhone 必测任务（本人可借设备或请亲友按清单操作，无需现在购买）：

1. 微信收到链接后转 Safari，添加桌面，从图标进入。
2. 中文键盘、金额键盘、日期/类别/账户选择、边缘返回和屏幕安全区。
3. 样例记账后关闭重开、重启、断网进入，核对记录；重复打开不重复补记。
4. 导出备份到“文件”，重新选择文件恢复并比对。
5. A → B 版本更新，非空账本和自定义类别保留。
6. 浏览器入口和桌面独立入口是否共享/分离数据、添加前后迁移和提示是否正确；不能未经验证假设两入口共享存储。
7. 在独立测试来源、只有可恢复的示例数据且用户明确同意时，检查移除图标、删除网页应用、清理站点数据的实际影响，记录 iOS 版本和具体操作。

无真机时可完成开发与模拟测试，但状态必须写“待 iPhone 验收”，不得宣称苹果正式可用。出现静默丢账、错账、无法备份恢复或更新破坏数据时停止试用推进。

## 阶段 6：固定 HTTPS 地址与小范围试用

先核验免费静态托管条款、HTTPS、资源路径、内容类型、Service Worker 范围和移动网络可访问性。测试来源与正式来源分开；正式地址在首批试用前确定，避免用户存账后频繁迁址。

部署预览可用于真机验收；正式发布、改动公开托管配置及群发链接按届时具体授权执行。本计划不代表已部署。

通过真机验收后，先邀请 1—3 位苹果用户从示例账本开始，观察独立安装、记账、离线打开、备份与更新。待用户可独立完成并有完整证据，再逐步扩大使用。提供中文安装说明、数据说明、版本记录和反馈模板。
