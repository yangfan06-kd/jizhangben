- 设备：小米 `2410DPN6CC`，Android 16／API 36，WebView Chrome 143.0.7499.192，系统字体比例 1.0。
- 独立检测应用：`com.jizhangben.app.qa`，界面名称“记账本检测”，版本 1.95／96。仅包名、显示名称和检测构建路径不同；34 个网页 JavaScript 文件与当前 1.95 源码逐一 SHA-256 比对一致。
- 测试使用两个模拟账本、一个原有模拟流水及测试账户，不导入正式用户数据。正式应用保持 1.94／95，不安装覆盖、清除数据或操作其页面。

## 观察与限制

渲染崩溃后，调试服务暂时同时保留旧的失效页面和新的可见页面，Playwright 通用重连超时。检测改为限定检测包与重建后的新页面，通过直接 CDP 状态读取和坐标点击完成核对。连接失败不等于应用恢复失败；原生日志、实际屏幕、新页面交互和数据断言构成恢复证据。

SDK 在重建早期出现短暂的 `triggerEvent` 及安全区域 CSS 注入日志，本轮可见页面和输入流程恢复正常；未逐项验收重建后的所有原生桥接操作，不能把此结果表述为所有接口无错误。

真实崩溃只触发一次，没有开展长时间压力测试、不同 WebView 版本、多机型或持续崩溃循环；没有改变系统字体、导航模式或强制更改手机设置。此前 1.94 的键盘手动验收是独立证据。

Android 渲染进程退出后需要销毁失效的 WebView 并重建；本项目已接入的插件通过 Activity 重建处理，测试检查实际 `onRenderProcessGone` 结果。[Android 官方终止处理说明](https://developer.android.com/develop/ui/views/layout/webapps/handle-termination)
