# 阶段 0：现状审查与独立原型（2026-10-15）

## 交付与边界

阶段 0 已完成：补录 [产品事实](../PRODUCT.md)、[现有设计基线](../DESIGN.md) 及设计工具的基线侧表，制作 [三个页面的交互原型](prototypes/stage0/index.html)，保留当前界面的合成数据截图供对照。

本轮不修改生产 `index.html`、`css/`、`js/`、Android 配置、依赖或用户数据，不构建新版 APK，不安装手机，不推送。原型不读取生产脚本、浏览器存储、接口或 Capacitor 桥接。所有名称与金额均为虚构示例，刷新即恢复。

原型只用于评估排版和交互。专项类型完整结算、账户余额服务、密码、导入和真实删除仍以正式实现为准，未在原型中另写一套业务规则。

## 原型可操作范围

- 顶部切换首页、记一笔、类别管理；右侧或手机下方切换新版方案／当前截图、文字大小、空状态与一次保存失败。
- 首页小眼睛同时遮挡净资产与其他资金；期间行查看对应示例范围和汇总；底部进入录入页。
- 支出、收入、转账可在预览内录入，确定直接提交并留在原页。收入允许负数，转账不显示类别；收入与转账不继承餐饮／微信。
- 加减输入实时显示结果与小字过程。备注输入时自制键盘收起；再次点金额可打开。专项记账只展示布局和范围说明，不执行虚构的结算规则。
- 点类别小类编辑名称与图标，可只换图标；取消不保存，失败保留旧设置和草稿；重试成功才更新预览。
- 新增小类可用箭头展开和收起；明确点击添加才增加。大类改名在名称旁展开输入。
- 小类长按约 320ms 后拖动排序；长按前移动超过约 12px 作为浏览处理；桌面还可用组合方向键辅助排序。触摸设备的手感尚未实测。
- 从记一笔进入类别管理，再返回时保留金额与原页面；对话层关闭后恢复背景交互和焦点。直接从预览导航进入类别管理时返回首页。

账户、报表、预算、基金、设置等保留入口，但本次只弹出“预览范围说明”，不意味着正式版本应改用这些弹窗。正式实现继续专项页面跳转。

## 浏览器验证结果

第二轮最终取得 **68 项检查通过、0 项失败、0 个页面脚本异常**。其中 45 项为 5 组窗口 × 3 档文字 × 3 页面：

- 窗口：320×640、360×800、390×844、412×915、568×320。
- 文字：标准、页面文字放大 130%、200%。没有整页或主屏幕横向溢出；类型条内部横向浏览属于设计行为。
- 交互：隐私及净资产遮挡、实时结果与过程、确定保存留页、非支出默认隔离、转账字段、来源返回、编辑取消、失败保留与重试、抽屉、键盘排序和鼠标长按拖动、长按前滑动抑制误点、负收入汇总、期间汇总、弹层焦点隔离与关闭恢复、备注与自制键盘避让。
- 原型来源的浏览器持久化存储逐项前后一致。此结果仅针对独立预览，不代表正式应用的存储逻辑重新验收。

第一轮 60 项通过，发现“从类别管理返回时误回首页”，已修复并在第二轮通过。最终验证早期的脚本因汇总选择器同时命中多行而中止，收窄为汇总区域后重跑；未改应用来迁就测试，也没有把未完成的测试报告为通过。

原始脚本、测量、截图与结果位于本机忽略目录 `output/playwright/stage0/`。当前截图位于原型 `baseline/`，可以随原型一起查看。

## 设计检测器的结果与解释

Impeccable 对独立原型运行一次，得到 93 条提示，不能把它们直接等同于 93 个实际缺陷：

- 90 条是颜色、字号、圆角偏离当前 `DESIGN.md` 的提示。本轮正是在比较候选值与旧实现，因此保留差异，不为消除提示而把候选值提前写成生产规范。
- 1 条为手机预览工具栏的 10px 说明字，已改为 11px，并以最终浏览器计算样式断言验证。
- 1 条是外部设备预览框采用贴边画布。框内应用已有留白，这是对照容器，不是内容贴边缺陷。
- 1 条是金额光标的 2px 竖线被识别为装饰侧边线。光标是用户明确要求，保留。

未把检测器当作会计规则、真实设备适配或性能证明；不安装自动执行钩子，也没有为了通过检测替换图标或用户数据。

## 尚未验证及下一步

本轮没有 Android 系统字号、真实输入法、手势导航、机型差异、崩溃恢复、APK 覆盖升级、导入备份或长流水性能测试；生产代码没有改变，因此没有重复全套业务测试和 APK 构建。

阶段 1 只将首页中已明确的层级、紧凑入口与点击区域改进落到生产展示层；不把原型代码整段复制进应用。类别删除入口迁移、字段排列等候选留到各自阶段再核对用户反馈。每轮继续保留原有财务、离线、隐私和数据兼容规则。
