# 阶段 6：大账本性能测量与候选包（2026-10-17）

已完成性能部分和离线候选构建；真机适配、家庭任务及正式覆盖升级仍待验收，不能将整个阶段标成完成。本轮没有安装、操作手机账本或推送 GitHub。

## 瓶颈及改动

开始时保存了工作区源码快照，没有用 Git HEAD 替换现有未提交改动。同一份合成账目下，首页及跨账本总览仍反复查找退款、报销、借贷、代付与押金；旧临时索引只覆盖流水列表／筛选。7,800 笔混合关联账目使桌面浏览器完整同步刷新达到 3,317.2ms，具有明确的局部优化依据。

| 文件 | 改动 |
| --- | --- |
| `js/records.js` | 复用原临时索引，增加借贷、代付与押金未结清关联查找；净资产计算进入同步作用域。押金最终结算与净资产对空关联／数字零编号的原语义不同，使用独立内部映射保留差别；不占用任何用户可定义类型名称。 |
| `js/view.js` | 首页统计与完整刷新进入同一临时计算作用域，嵌套使用同一数组时复用，退出包括异常时释放。原各页面绘制顺序与调用保留。 |
| `js/overview.js` | 总览绘制使用当前账目的临时作用域；各账本净资产按其独立数组计算，结束恢复外层上下文。 |
| `tests/records.test.cjs`、`tests/render-and-draft.test.cjs` | 增加四项回归：独立净资产／逐账户预期，旧关联语义，跨账本／异常／原数组编辑删除，首页统计重新读取变化。 |
| `tests/fixtures/home-records.cjs`、`tools/bench-home*`、`tools/verify-home-baseline.cjs` | 可重复夹具、前后测量及逐条旧结果对照。测试运行时增加可选源码根目录，只用于加载本轮开始快照。 |

与开始摘要比较，生产源文件仅上述三个 JS 改变。HTML、CSS、类别及图标模块、存储键和格式、金额精度、基金结算、退休金补记、隐私、草稿及返回逻辑均未修改。没有跨刷新缓存或持久化索引，也没有引入新依赖或虚拟列表。

## 样例与测量方法

每组 26 笔：跨月原支出及超额退款／报销、部分及最终押金退回、借入偿还／借出收回、代付收回与无法收回、未结清的付／收押金、负收入、基金本金转账／收益结算、信用卡支出、退休金收入及普通消费。

独立预期：每组全部收入 235 元、全部支出 675 元、本月收入 235 元、本月支出 375 元，净资产较初始减少 440 元。逐账户余额另有独立预期，不能只用被测函数自己证明自己。所有样例生成于 VM／独立浏览器来源，不读取真实手机、备份或正式账本。

同机 Intel Core i7-14650HX、Node v24.19.0，桌面 Edge 155、390×844。混合样例每项预热一次，再执行三次取中位数；不计夹具生成。浏览器计时包含同步函数和强制布局，不包含真正呈现帧、冷启动或长期内存。运行环境并非完全隔离的实验室，表中小差值不作性能收益结论。
