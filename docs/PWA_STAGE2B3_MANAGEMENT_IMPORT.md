# 苹果离线网页版：阶段 2B3 管理与导入事务接入

日期：2026-11-12。状态：本批已完成；阶段 2 的本机开发验证完成。独立存储预览仍未替换普通原型，没有安装手机、发布站点或推送 GitHub。所有测试只使用仓库合成账本，未读取或改动真实用户账本。

## 改动范围

存储接入预览现在开放账本新增/修改/切换/删除、类别与自定义类型管理、预算、JSON 恢复和 CSV 导入。变更在同一 IndexedDB 事务提交，事务完成后才清空表单或刷新成功页面。数据库版本冲突时拒绝旧窗口覆盖，保留本窗口输入。

产物为 `output/pwa-storage-preview/`，共 50 个明确允许的文件；普通原型仍单独输出 46 个文件，并使用原浏览器存储。两者没有 Service Worker，尚不能离线冷启动，不适合存放唯一正式账本。

### 文件位置

- `pwa/management-storage.js`：新增管理事务控制器。包含账本与关联键的联合提交、类别元数据提交、预算变更、导入替换和导入新账本。错误提示为中文，保存失败不清输入；提交已成功但页面刷新失败时单独提示，避免把它误报为保存失败。
- `pwa/app-storage.js`：开放已接入的管理入口；启动前检查基金与管理事务模块均已加载，缺失时停止进入账本。服务端迁移和已无页面调用的旧本金入口仍不开放。
- `pwa/fund-storage.js`：管理编辑和导入期间暂缓自动补记；离开编辑或提交完成后继续沿用原有补记规则，避免重绘覆盖输入。
- `js/book-form.js`、`js/budget.js`、`js/custom-options.js`：增加仅在 PWA 管理控制器存在时使用的委托；安卓继续执行原分支。
- `js/category-system.js`：排序、改名、图标及新增/删除等待 PWA 提交结果；同步的安卓调用仍保留原结果类型。小类图标、名称和历史关联不会提前显示保存成功。
- `js/backup.js`：PWA 恢复委托；将读取和提交后的页面刷新分开，避免失败时重置输入。
- `js/external-import.js`：提取共享的新账本写入函数；PWA 可在事务中调用，安卓保持原调用顺序。确认前保存来源文件名与列映射快照，避免异步确认过程中串用另一个文件的信息。
- `pwa/build.cjs`、`pwa/public-files.json`：管理模块只加入独立存储预览，按数据库、存储适配、基金、管理、应用启动的顺序加载。
- `tests/pwa-management-browser.js`、`tests/pwa-ordinary-browser.js`：管理与普通存储分支的真实页面检查；测试脚本、夹具和日志不进入发布产物。

修改前 14 个文件的副本、哈希、完整未提交差异和状态清单位于 `backups/pwa-stage2b3-before-20261112/`。原有未提交改动保留，包括报销使用支出类别选择器的分支；本批未修改页面 CSS、类别图标资源、Android 包名或签名。

## 数据与交互规则

1. **账本**：删除当前账本时，账本清单、当前选择和该账本的流水/账户/预算/旧定投/基金/退休金关联键一起提交；失败恢复原状态。切换成功后才重置筛选与编辑状态。明确保存为空的账户列表不会因切换或重开被默认账户替换。
2. **类别**：名称、图标、小类归属、顺序及隐藏项联合保存；不批量重建用户配置。沿用现有规则：支出小类改名同步各账本旧流水及预算；收入改名只影响今后的选择，旧流水保留原名称。移除类别不删除历史流水。
3. **操作区分**：普通点击进入小类编辑，长按拖动排序；新增小类仍由箭头抽屉展开/收起。取消不写入，失败保留编辑值与图标选择，排序失败恢复原位置。
4. **预算**：总额度和分类额度仅改变预算数据，保存失败保留金额输入，不提前清空或显示成功；不改变收支统计和账户余额。
5. **JSON 恢复**：读取并校验后再确认整份替换；取消或损坏不写入。替换与既有兼容加载在同一事务，失败不留下半份备份。旧 localStorage 原副本不删除，也不会在重开时再次覆盖已初始化数据库。
6. **CSV 导入**：沿用预览及确认，按来源分别新建账本。新账本、记录、账户及新增类别在一个事务内保存；失败保留预览可重试，不残留空账本或孤立账户，也不覆盖现有账本。导入后重新读取新账本的基金和退休金状态，避免沿用前一账本的数据。
7. **设备偏好**：隐私隐藏、密码和信任设备设置继续与账本分开；恢复备份不替换这些本机偏好。
